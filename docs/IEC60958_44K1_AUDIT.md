# 44.1 kHz PCM / ARC 标准核对记录

日期：2026-10-12。对象：当前工作区的 C1 TF 播放、推挽 SPDIF，经外部电路接 Samsung Q900T ARC。

## 结论与证据边界

对照用户提供的 IEC 60958 文档，当前普通双声道 PCM 的基础帧结构、采样位对齐、有效位、奇偶校验，以及 44.1 kHz/16 位的核心声道状态字段，没有发现明确编码错误。不能由此宣称完整符合所有版本标准，也不能证明 HDMI 接口上的实际波形正确。

用户实测：同板光纤可播放原始 44.1 kHz WAV；ARC 可播放其 48 kHz 重采样版本；111 MHz 时钟试验仍不能使原始 44.1 kHz 经 ARC 出声。降低平均频偏未解决问题，但该实验未消除 PIO 分频抖动、晶振误差、接口失锁或电气问题。

有两项描述完善问题：类别码一直使用临时 General；2021 版新增的声道分配等扩展字段没有完整实现。两者都不能直接解释目前的采样率选择性故障。

## 实际编码输出

编译当前 `src/spdif_encode.c`，从其输出的 BMC 转换位流独立恢复 C 位，得到以下 24 字节。此结果来自主机软件，不是接口抓波。

```text
44.1 kHz / 16-bit L: 04 00 10 00 02 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
44.1 kHz / 16-bit R: 04 00 20 00 02 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
48   kHz / 16-bit L: 04 00 10 02 02 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
48   kHz / 16-bit R: 04 00 20 02 02 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
```

相同字长下，44.1 与 48 kHz 的状态块只差 byte 3 的采样率字段。标准表格常按低编号 bit 在左的传输顺序写二进制，不能直接把该字符串当作通常的高位在左二进制数。例如 bits 24..27 的 `0 1 0 0` 对应数值 `0x02`，即 48 kHz。

## 基础 PCM 帧核对

| 核对项 | 固件行为 | 判断与依据 |
| --- | --- | --- |
| 子帧与左右声道 | 每子帧 32 slots，每帧 L/R 两子帧 | 符合 Part 1 §4.1 |
| 16 位采样位置 | WAV 符号扩展后左移 8，再置入 slots 4..27；实际有效位 slots 12..27，其余低位为零 | 符合 §4.1.1；并不是把 16 位放到 slots 4..19 |
| 24 位采样位置 | 有效位 slots 4..27 | 符合 §4.1.1 |
| 正负采样 | 线性二进制补码，MSB 在 slot 27 | 符合 §4.1.1 |
| 前导码 | 每块首个 L 用 B/Z，其余 L 用 M/X，R 用 W/Y | 符合 §4.1.2、§4.3、Table 1 |
| 前导码编码 | NRZI 转换掩码为 0x39/0xC9/0x69，积分为标准 B/M/W 电平序列 | 不应直接将掩码和标准的电平序列字节比较 |
| BMC | 每数据位边界翻转，逻辑 1 在中间再翻转 | 符合 §4.2 |
| V 位 | 普通有效 PCM 为 0 | 符合 §4.4；C1 的 PCM 静音备用块同样为 V=0 |
| U 位 | 0 | 符合 Part 3 §4、§6.1 的默认用法 |
| P 位 | slots 4..31 偶校验 | 符合 Part 1 §4.1.1 |
| C 位 | 每声道 192 位，B 前导码帧携带第 0 位，字节内低位先发 | 符合 Part 1 §5.1、Part 3 §5.1 |
| 普通 PCM 的封装 | 直接 IEC 60958 子帧 | 不需要增加非线性压缩音频的 IEC 61937 burst 前导 |

代码位置：`src/wav_reader.c`、`src/spdif_encode.c`、`src/spdif.pio`、`src/spdif.c`。

## 声道状态逐字段核对

| 字段 | 当前值 | 判断 |
| --- | --- | --- |
| byte 0 bit 0 | 0 | Consumer；不能套用 Part 4 Professional 的采样率字段解释 |
| byte 0 bit 1 | 0 | Linear PCM；未误标为 AC-3/DTS |
| byte 0 bit 2 | 1 | 固定声明版权未被主张；不是从 WAV 元数据推导。属于源描述策略，不能据此认定导致静音 |
| byte 0 bits 3..5 | 000 | 2-channel，无预加重；未启用 Part 5 增强模式 |
| byte 0 bits 6..7 | 00 | Mode 0 |
| byte 1 | 0x00 | General，标准标明临时用途，见下文 |
| byte 2 | L=0x10/R=0x20 | Source=0（不考虑）；channel=1/2，符合立体声左右定义 |
| byte 3 bits 24..27 | 44.1k=0x0，48k=0x2 | 正确。44.1k 的 0 不是“未指定”；未指定为 0x1 |
| byte 3 bits 28..29 | 00 | Level II；不是“没有时钟”。不能把此声明当作实际精度测量 |
| byte 4 bits 32..35 | 0x2（16 位）/0xB（24 位） | 正确。bit32=0 指最大 20 位容器，不代表实际有 20 位有效采样 |
| byte 4 bits 36..39 | 0 | 原始采样率未指定，是 2006、2021 两版明确允许的默认值 |
| byte 5..23 | 0 | 符合传统实现的默认/保留位用法；不能泛化为完整实现 2021 的新增字段 |

原始采样率的结论应修正为：`0x02 -> 0xF2` 对未经重采样的 44.1 kHz/16 位 PCM 可以做兼容性 A/B 测试，但不是纠正必需字段缺失。若将来加入重采样，原始采样率与传输采样率不能混为一谈。依据：2006 PDF 第 15–16 页；2021 PDF 第 18 页及 Annex P。

## 需要完善、但尚未证明与无声相关的描述

### 类别码

当前 `byte 1=0x00` 是 General。2006 §5.3.2.2.1（PDF 第 17 页）和 2021 §5.3.2.3（PDF 第 21 页）限定其为临时用法并说明特定广播场景。

TF 本地播放有更准确的类别：Table 11 的固态存储录放设备，bits 8..15 为 `0001000L`，即低七位数值 `0x08`，最高位 L 需按源属性处理。不能因为从 TF 播放，就自动断定 L 的值，也不应把 USB 等其他输入一概标成 TF。

这是产品描述准确性问题；44.1/48 kHz 使用相同类别码，没有证据证明它导致本次差异。若实验，只改这一项，保留时钟和其他字段。

### 2021 新增描述

2021 §5.2.2 对 byte 5 的有效性/频率系数、byte 6/7 的 General Channel Assignment 等赋予了新定义。当前实现没有完整支持这些扩展，不能声称全面符合 2021 版。

尤其是 General Channel Assignment 的零值不能直接按旧版“保留位零”解释为未指定：PDF 第 19 页列出的 A/B 零编码均指向 channel number 1，而当前两字节都是零。该页字段范围与表头位号还存在不一致，且具体声道位置另引用 IEC 62574:2020（未提供）。因此记录为新版字段一致性待确认，不据此盲改字节，也不认定为 Samsung 的静音原因。传统 byte 2 左右声道号已经是 1/2。

Part 5 的增强格式不适用于当前普通双声道 16 位模式。为排查这次问题，不应通过启用增强模式扩大变量。

## 后续定位顺序

1. 读取 Q900T 的 ARC LPCM SAD，确认它在 ARC 路径实际报告的采样率。当前 `cec_tv.c` 没有 SAD 请求/解析流程；Pico 提供给对端的 EDID 不是 Q900T 的 ARC 接收能力。此项需依据 HDMI/CEC 规范另行实现，不从 IEC 60958 推导 opcode 语义。
2. 若要先做状态字段兼容性实验，保持已经试过的时钟配置，仅把原始 44.1 kHz WAV 对应的 OSF 写成 44.1 kHz（byte 4=0xF2）。结果为正才能说明接收端对这个默认值敏感。
3. 将类别码准确化作为独立实验。不要同时改 OSF、类别码、左右声道号和时钟，以免结果无法归因。
4. 在 C1 GPIO 和 HDMI ARC 电路输出分别抓取 44.1 kHz 波形、解码完整 192 帧 C 块，检查前导码、V/P、连续性，并记录 UART 的 `under`、`dma0`、`txstall`。软件编码正确不等于线路接收正确。
5. 若有已知能让 Q900T 经 ARC 播放 44.1 kHz 的发送器，比较其线上 C 块与电气波形；光纤成功仅证明另一条接收路径可工作。

本次只记录审核结果，没有改动 SPDIF 编码字段，也没有生成未经用户实测的新修复结论。
